# BohdiAI Codebase Audit — 2026-06-10

**Prepared as an independent third-party review.**
**Branch audited:** `session-12/layout-engine` · **Method:** four parallel read-only review passes (security & tenant isolation, dead/stale code & repo hygiene, engineering practices, data layer & migrations), plus direct auditor verification of the headline finding. The live Supabase database was queried read-only for RLS/index/policy facts. No code was modified.

---

## Verdict in plain English

The recent demolition work was clean — that is the headline good news. Across all four passes we found zero dangling imports to the deleted modules, zero unused dependencies, no secrets in git, `.env.local` properly ignored, `tsc` passing on the strictest config, and no `any` in the shipping code. RLS is enabled on all 33 tables, foreign keys cascade correctly, and the subdomain lookup is indexed. For a codebase that just had whole sections ripped out, the wreckage was swept up well.

The problem is the **security boundary on the live storefront**, serious enough to fix before any real traffic. Tenant isolation currently lives entirely in application code, and the one thing holding it together is a request header the proxy forgets to strip. That, plus a wide-open admin route and unauthenticated AI endpoints that cost real money to hit, are the launch-blockers. Everything else is hygiene and hardening.

Two cross-cutting root causes recur: **auth was never wired in** (the app was built assuming it lands later), and **the type layer drifted from the live DB** (so several writes cast around the generated types). Fixing those two roots clears roughly a third of the list.

## Critical — fix before any production exposure

### C1. Tenant isolation is bypassable via a forged `x-tenant-id` header

`proxy.ts:31` copies all inbound headers (`new Headers(request.headers)`) and only ever *sets* `x-tenant-id` (line 33) when a subdomain resolves — it never deletes an inbound one. On the apex / `app` / `admin` host no tenant resolves (`subdomain === null`), so no rewrite happens and a client-supplied header passes through untouched. Every storefront page then trusts that header and reads with the RLS-bypassing **service-role** client:

- `app/storefront/subscriptions/page.tsx:34` reads `x-tenant-id`; line 37 `supabaseAdmin()`; line 42 `.eq('tenant_id', tenantId)`.
- Same pattern in `app/storefront/layout.tsx`, `app/storefront/_components/LegalPage.tsx`, and the other storefront routes.

**Confirmed exploit (verified by the auditor):**
`curl https://bohdiai.com/storefront/subscriptions -H 'x-tenant-id: <victim-uuid>'` → proxy sees apex host, no rewrite, forwards the forged header → page queries the victim tenant's listings with the service role and returns them, including unpublished `is_preview` rows and `contact_email`.

RLS is enabled on every table but is **not** the active boundary on this path — a forgeable header is. Tenant UUIDs being random raises the bar to exploit, but the architecture is the defect.

**Fix:** In `proxy.ts`, unconditionally `requestHeaders.delete('x-tenant-id')` and `delete('x-tenant-subdomain')` at the top, before any conditional `set`. Block `/storefront/*` when no subdomain resolved (return 404). Defense-in-depth: run storefront reads through an anon/RLS-scoped client so application code is not the only isolation boundary.

### C2. The admin route is completely unauthenticated

`app/api/admin/tryon/route.ts:11` — the file's own header reads "No auth yet — dev/founder only; gate before this ships." No auth, no rate limit, `maxDuration = 300`. Anyone reaching it can target any tenant by `subdomain`, run a full archetype conversion (Anthropic + fal.ai spend), and persist a new store version against that tenant. There is no founder/admin authentication anywhere in the app yet.

**Fix:** Supabase session + founder allowlist before this is deployable; add it to the rate limiter; reject callers who are not the tenant owner or a founder.

## High — cost/abuse exposure on unauthenticated paths, and integrity gaps

### H1. AI generation endpoints are unauthenticated

`app/api/onboarding/generate/route.ts:37`, `app/api/onboarding/start/route.ts:21`, `app/onboarding/actions.ts:54` all kick off `runStorefront` (Anthropic + fal) with no authentication — only an IP rate limit. Next server actions are public POST endpoints, so the action is callable directly too. **Fix:** require an authenticated onboarding session; keep the IP limit as a secondary control.

### H2. The generation rate limit is weak, fails open, and races

`lib/rate-limit.ts:6` `const MAX_PER_WINDOW = 20; // TODO: reset to 3 before launch`; the limiter returns *allow* on any DB read error (fails open); and the read-then-update (lines 22-57) is not atomic, so concurrent requests can all pass. **Fix:** lower the cap, make it atomic (single `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING` with a count guard, or a Postgres function), and fail closed on the expensive endpoints.

### H3. Contact endpoint has no rate limit

`app/api/contact/route.ts:63` `// TODO: per-IP rate limit before launch.` Unauthenticated; emails the tenant's `contact_email` via Resend on every call; enumerable UUIDs → inbox flooding / Resend reputation. The HTML body is correctly escaped (no injection) — the issue is volume. **Fix:** per-IP limit + per-tenant cap before launch.

### H4. No transaction across the three storefront inserts — half-built stores persist

`lib/generation/write-archetype-storefront.ts:42-110` inserts `tenants` (47), `content_pages` (77), `listings` (105) sequentially with no transaction. A failure mid-way orphans the tenant row, or leaves a published store with no products. **Fix:** wrap in a single Postgres RPC (transactional), or insert the tenant as `status: 'draft'` and flip to `'active'` only after all writes succeed. This file is also the most consequential in the live path and **has no test** — add an integration test covering the partial-failure path.

### H5. API routes don't validate input with zod

`lib/validation.ts` exists but `app/api/onboarding/generate/route.ts:38` and `start/route.ts:22` cast `await req.json() as GenerateBody` and validate only `moodKey`. `subdomain` flows unvalidated into storage paths (`product-images/${subdomain}/...`) and DB rows; `shopName`, `nicheSlug`, `productCount`, `logoUrl`, `brandColors` are trusted. **Fix:** define zod schemas and parse both bodies at the boundary; reject with 400. This also removes the `as` cast.

## Medium

- **Type layer drifted from the live DB.** `lib/database.types.ts` is missing `design_choices`, `style_sheets`, `store_versions`, `builds`, and the actively-used `tenants.logo_url` column. That drift is why several writes cast around the types (`lib/onboarding/build-store.ts:30`, `lib/onboarding/crew/log-choices.ts:60`, `lib/generation/write-archetype-storefront.ts:45` — `as unknown as {...}`, which the Engineering Standards ban). **Fix:** regenerate types from the live schema, then delete the casts. One move clears a TypeScript-discipline finding and a data-drift finding together.
- **Build-status writes swallow DB errors silently.** `lib/onboarding/build-store.ts:50-73` — `markRunning` / `updateLabel` / `completeBuild` / `failBuild` discard `{ error }`. If `completeBuild` fails, the maker's build screen spins "running" forever. Violates the "no silent failures" Golden Rule at a user-visible boundary. **Fix:** check and at least `logger` the error; `failBuild` especially must not fail silently.
- **Cumulative pipeline timeout exceeds the route ceiling** (the recent timeout symptom). Crew stages run sequentially — director 60s + copywriter 180s + cinematographer 60s + graphic-artist 90s + cut 120s = up to 510s worst case — against `maxDuration = 300` (`generate/route.ts:20`). `pipeline.ts:77-83` runs them in series with no global budget. **Fix:** add an overall pipeline deadline under 300s, or trim the copywriter's 180s (60% of the route budget).
- **Open redirect in auth callback.** `app/auth/callback/route.ts:15` — `next` concatenated unvalidated into the redirect; `next=//evil.com` redirects offsite (phishing). **Fix:** require a single leading `/`, reject `//`, or allowlist paths.
- **SVG logo upload to a public bucket, no auth, unsanitized path.** `app/onboarding/logo-actions.ts:9` allows `image/svg+xml` into the public `tenant-logos` bucket under a caller-supplied `subdomain` path with `upsert:true` and no auth. Stored-XSS vector if ever served same-origin; `subdomain` could contain `../`. **Fix:** drop SVG or sandbox it (attachment disposition, isolated origin), validate the path segment against `^[a-z0-9-]+$`, require a session.
- **AI-authored CSS interpolated into `<style>` without CSS-escaping.** `lib/style-sheet-loader.ts:75-104` concatenates palette/font values; injected via `dangerouslySetInnerHTML` in `StorefrontPage.tsx:260` and `storefront/layout.tsx:33`. Inputs are schema-constrained (hex-only, `z.string().url()`), so not weaponizable today, but a future schema loosening could allow CSS breakout. **Fix:** CSS-escape interpolated values; allowlist `customUrl` hosts.

## Low / hygiene

- **No CSP, no HSTS.** `next.config.js:24-35` sets `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` but no Content-Security-Policy or Strict-Transport-Security. Given multiple inline `<style>` sinks, both are worth adding (CSP needs care for the inline styles).
- **Phase-0 routes use raw `console.error`** instead of `lib/logger` (waitlist ×10, waitlist/resend ×3, confirm ×3, `app/page.tsx` ×2). Standards forbid `console` in production code; lint isn't enforcing it. The generation path is clean. **Fix:** switch to `logger`, add the `no-console` lint rule.
- **Lint error doesn't fail CI.** `lib/archetypes/main-street/chrome.tsx:240` raw `<a href="/">` is a lint *error*, but ESLint exits 0 so the Definition-of-Done gate isn't enforced. **Fix:** fix the link, add `--max-warnings 0`, ensure errors fail CI.
- **Dead dev/preview routes shipping in the app bundle:** `app/_reference/functional-studies/studies.tsx`, `app/archetype-test/**` (+ fixtures), and the orphaned `app/storefront/gallery/page.tsx` (Gallery archetype was deleted per D36 — `/gallery` is not in `SLUG_TO_ARCHETYPE_PAGE`, so it 404s for every tenant). **Fix:** delete or gate behind a dev-only check.
- **Two design mockups tracked in git** that shouldn't be: `procession-mockup.html` (Constellation replaced the procession) and `_design-mocks/`. Plus the untracked `skin-shelf.html` stray (generated by `scripts/gen-skin-shelf.ts`). **Fix:** untrack and/or gitignore. (All other loose artifacts — `*.log`, `tsbuildinfo`, `tmp/`, `coverage/`, `test-results/`, `lighthouse-*.json` — are already correctly ignored.)
- **Orphaned legacy schema.** The layout-engine deletion was code-only. The live DB still contains the `style_sheets` table and the `write_tenant_storefront` / `write_tenant_storefront_layout` RPC functions, called by nothing (the active path does direct inserts). Harmless but dead. **Fix:** add a DROP migration, or document them as intentionally retained. Assess `builds` / `store_versions` similarly.
- **Stale mood key in code.** `lib/archetypes/main-street/index.tsx:26` still lists retired `'simple'` (D51 renamed it to `elegant`). Tests already assert the retirement, so this list is inconsistent with the live lineup.
- **`!.` non-null assertions in shipping code** (banned by standards) — `lib/fal.ts:111,124,137`, `lib/onboarding/build-archetype-store.ts:49`, `lib/generation/write-archetype-storefront.ts:116`, and several Main Street layout components. All currently guarded by a preceding check, so low risk, but literal rule violations. **Fix:** narrow with a local const + guard.
- **`builds/[id]` IDOR (low impact).** `app/api/onboarding/builds/[id]/route.ts:14-25` returns build status with no ownership check. Random UUIDs, low-sensitivity data. **Fix:** tie builds to a session when auth lands.
- **Migration runner `--mark-applied` foot-gun.** `scripts/db-migrate.mjs:106-115` records a migration as applied without running it, the one way to silently diverge the DB from history. Deliberate tool; use sparingly and log its use.

## Verified clean (checked, no issue found)

- No secrets in tracked source (grep for `sk-ant-`, JWT shapes, `service_role`, private keys → only docs/migration comments).
- `.env.local` is **not** committed (`git check-ignore` confirms; `.gitignore` covers `.env*.local`).
- Service-role key never reaches the browser bundle — `supabaseAdmin()` imported only by server files; client uses the anon key only.
- No SSRF via `inspiration_urls` — the field exists in types but nothing fetches user-supplied URLs server-side.

- No unused dependencies (`pg`, `lenis`, `@material/material-color-utilities`, etc. all verified in use).

## Recommended remediation order

1. **Strip the header in the proxy (C1) and gate the admin route (C2).** Small changes; they are the difference between "isolation is enforced" and "isolation is a suggestion." Launch-blockers.
2. **Lock down the unauthenticated AI/email paths (H1–H3):** atomic fail-closed rate limit, reset the cap to its launch value, require a session.
3. **Regenerate the DB types and drop the `as unknown as` casts** — one move, clears the drift and the type-discipline findings.
4. **Make the storefront writes transactional and add the missing test (H4);** fix the silent build-status errors.
5. **zod-validate the API request bodies (H5);** then fix the pipeline timeout budget.
6. **Hygiene sweep:** dead routes, tracked mockups, orphaned schema, the `console.error` and lint-CI gaps, the stale `'simple'` mood key.

Items 1–2 are roughly an afternoon of work and clear every launch-blocker.
