# Codebase Audit — 5 July 2026

**Method:** Eight independent parallel audit agents, each covering a distinct dimension of the codebase. Findings synthesized here in plain English. Reference doc — not a live checklist. Every finding lives in a phase of `Full-Plan.md` for actual tracking.

**Scope covered:** Legacy code + naming, security, type safety + error handling, data integrity + database, performance, tenant renderer cleanliness + accessibility, documentation, config + CI + deps + tooling.

**Scope NOT covered** (revisit if wanted): image-storage lifecycle, try-on version-history model, the Cloudflare Worker source, Playwright E2E in depth, marketing site.

---

## Bottom line

The code is well-written where discipline has been applied. But the site has a handful of security holes that need to close before it can be shared with anyone. The Session 63 renderer cleanup was less complete than it looked. The docs describe a product model that no longer exists (fixed in Phase 0.1).

None of this is catastrophic. All of it is fixable, tracked in `Full-Plan.md` at the right phase.

---

## What's genuinely working

1. **Real code discipline.** Strictest possible TypeScript settings and the code still passes them. Zero `any`, zero `@ts-ignore` in production code.
2. **No customer-data leaks from tenant storefronts.** No XSS on tenant-authored content. Payments never touch us (matches spec §7).
3. **~4,000 lines of legacy code deleted this session with zero test failures.** Signals genuine decoupling between old and new.
4. **The tenant renderer has a real structural shape.** CSS variables, declarative type roles, reduced-motion, ready for the family layer.

## Findings by dimension

- Untracked one-off scripts (`build-soul-splatter-bright.ts`, `verify-fade.mjs`, `verify-zoom.mjs`, `test-main-street-archetype.ts`) sitting in working tree. Cleaned in Phase 0.2.
- Sixteen orphan test files whose subject files were staged-as-deleted. Cleaned as part of the path B removal.
- Two rate-limit TODOs marked "before launch" that would ship as-is if forgotten. Phase 6.

### Security
Two CRITICAL, eight HIGH, plus a scattering of MEDIUM. All in `Full-Plan.md` Phase 6.

- CRITICAL: `admin/tryon` page + API both unauthenticated. Anyone can enumerate every tenant + burn fal.ai budget.
- CRITICAL: `notify_interest` table missing RLS. Customer emails readable by anon. (Phase 0.3 — DONE.)
- CRITICAL: Rate limiter has three overlapping bugs — reads-then-writes race, fails OPEN on DB error, trusts spoofable `x-forwarded-for`. TODO to reset `MAX_PER_WINDOW` from 20 to 3 never done.
- HIGH: Onboarding endpoints (`/api/onboarding/start`, `/api/onboarding/generate`) accept anonymous POSTs and spawn full paid Bohdi builds.
- HIGH: Auth callback open redirect via `next` param.
- HIGH: Subdomain unvalidated, flows into image-storage folder paths — path traversal.
- HIGH: Build-status endpoint leaks any tenant's state to anyone who guesses a UUID.
- HIGH: Vercel origin bypass — anyone can hit `bohdiai.vercel.app` directly and set `x-bohdi-shop` themselves, sidestepping Cloudflare.
- MEDIUM: `/signin` accessible on tenant subdomains — phishing surface (a maker's shop can present a login form on `their-shop.bohdiai.com/signin`).
- MEDIUM: Contact form + Notify Me + Waitlist + Waitlist Resend all lack rate limits.
- MEDIUM: Confirm route leaks "at least one confirmed row exists" via a fallback query.

### Type safety + error handling
Genuinely clean by strict measures. Real issues at the boundaries:

- HIGH: Anthropic tool schemas across four crew stages (copywriter, cinematographer, graphic-artist, directors-cut) are `{ properties: {}, additionalProperties: true }` — no validation at tool-use boundary. Malformed responses burn retries. Phase 1.
- HIGH: `withTimeout` rejects but never aborts the underlying Anthropic/fal call. Under retry pressure, timed-out calls keep running. Phase 1.
- HIGH: `~12 files` used `as unknown as {...}` shims around `supabaseAdmin()`, dodging generated types entirely. Phase 0.3 — DONE.
- HIGH: `/api/onboarding/start` and `/api/admin/tryon` accept `req.json() as {...}` without Zod. Phase 6.
- MEDIUM: `lib/fal.ts` interpolates `moodSignal!.moodLabel` after a guard that doesn't check `.moodLabel`.
- MEDIUM: `app/api/onboarding/start` uses unawaited `void updateProgress()` calls that swallow errors silently.
- Resend errors are `console.error`'d and the user sees "confirmed" — no delivery signal.

### Data integrity + database

- HIGH: Four dead tables (`page_blocks`, `design_tokens`, `style_sheets`, `editor_history`) polluted schema + generated types. Phase 0.3 — DONE.
- HIGH: Build pipeline race — `persistCollections` runs AFTER tenant status flips to `active`. A visitor hitting `/collections/[slug]` in that window gets 404. Phase 1.
- HIGH: `commitLook` writes envelope + `mood_key` as two statements with no rollback.
- HIGH: Rate-limit read-modify-write race condition (see Security).

- HIGH: Storefront home listings/collections queries omit `status='active'` + `is('deleted_at', null)`. Phase 1.
- HIGH: `content_pages.layout_tree` JSONB has no runtime validation on read — a drifted envelope crashes deep in render. Phase 1.
- MEDIUM: `.single()` used where `.maybeSingle()` fits (LegalPage crashes 500 on a suspended tenant).
- MEDIUM: `/api/onboarding/start` has no idempotency check on subdomain — double-click starts two parallel builds. Phase 6.
- MEDIUM: No Stripe webhook handler exists yet (Phase 6 build).

### Performance
- CRITICAL: Crew pipeline retry budget can exceed 300s serverless ceiling (copywriter 4 × 90s = 360s). Phase 1 caps retries to 2.
- CRITICAL: `withTimeout` doesn't abort underlying calls (see Type safety).
- HIGH: Same home envelope loaded 3-4× per request (`layout.tsx` for JSON-LD, `storefrontSeoFacts`, `StorefrontPage`, sometimes twice). Phase 1 consolidates.
- HIGH: 5 sequential DB round-trips per home render — should be parallel. Phase 1.
- HIGH: Nine display components had unnecessary `'use client'` shipping to the client bundle. Phase 0.4 — DONE.
- HIGH: Three unused runtime deps (`lenis`, `framer-motion`, `@material/material-color-utilities`) shipping unused. Phase 0.2 — DONE.
- HIGH: Hero and product tiles use raw `<img>` — no `next/image`, no `priority`/`fetchpriority`/`sizes`. Deferred.
- MEDIUM: `proxy.ts` calls `supabase.auth.getUser()` on every request including storefront reads.
- MEDIUM: `Reveal` wraps every above-fold beat as a client component — every one is a hydration boundary and hides content until JS runs.
- LOW: No `Cache-Control` / `s-maxage` on storefront routes — CDN can't do stale-while-revalidate.
